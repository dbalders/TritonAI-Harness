# Integration-only Codex build

This build applies the reviewed patch to the exact upstream source and verifies every changed file before and after compilation. It requires the Rust/Cargo version in `contract.json`; it does not install a toolchain, sign, publish or install the resulting executable.

After installing the Harness workspace dependencies, run `vp run build:integration-codex`. The default output is under the checkout's `.t3/native-build/codex-integration/`. `--help` lists explicit source, output, compiler and development-profile options. Existing source changes or output from another contract are preserved and refused.

The dedicated process accepts `--harness-integration-policy` with a bounded JSON document containing `protocol: "tritonai.codex-integration-only/v1"` and `tools: ["exact_dynamic_tool_name"]`. It captures that ceiling once. Its model-facing router contains only those dynamic callbacks, with no native execution tools, hosted tools, inherited extensions, skill discovery, hooks or MCP connections. Trusted client control-plane RPCs still exist; this is a model-tool ceiling, not an OS sandbox for plugin code. Cold native history restoration is refused. Host callbacks still need their own live session, catalog/schema checks and exact write approval; this ceiling grants no write authority.

The unsigned build receipt identifies bytes and inputs. It is not a release signature or authority to trust an arbitrary executable. The environment maintainer must independently verify the source/build and set `TRITONAI_INTEGRATION_CODEX_BINARY`, `TRITONAI_INTEGRATION_CODEX_SHA256` and `TRITONAI_INTEGRATION_CODEX_CONTRACT_SHA256` in the server's startup environment. The binary path must be absolute. These pins cannot be supplied through provider settings or tool arguments; copying a downloaded artifact's own claimed digest does not establish trust. The launcher checks a private executable snapshot against this pin, then checks its startup receipt against the host's exact callback policy before installing a session lease. Missing or mismatched composition fails closed. This build command does not set the pins or install the runtime.

A Codex provider instance with Agent purpose set to `integrations` selects this launcher. Coding sessions withhold plugin callbacks and plugin skills. The integration profile excludes browser, computer-use and general Harness MCP tools. Its callbacks retain the ordinary connection checks and per-write review. Native cold restoration and exposed forks remain unavailable pending host-validated history reconstruction; they must not fall back to a coding process.
